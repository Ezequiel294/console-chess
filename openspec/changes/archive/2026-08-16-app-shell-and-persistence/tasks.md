## 12. Post-implementation revisions

Playtesting after 1–11 landed surfaced real problems; addressed in place rather
than as a separate change, since nothing here had shipped yet. See `specs/`
and `design.md` for the corresponding requirement changes.

- [x] 12.1 Menu consistency: every choice screen (main menu, settings, the
      resignation picker, confirm overlays, the result screen) now supports
      up/down + Enter and a mouse click, not just some of them; confirm
      overlays gained left/right + Enter alongside Y/N
- [x] 12.2 Replaced the three fixed save slots with a `games/` directory: any
      number of saves, each its own file named by date and time, so saving is
      instant (no picker, nothing to overwrite) and loading is a scrollable
      dated list
- [x] 12.3 Fixed the Help screen's own "Esc close" hint colliding with its
      last content line on shorter terminals; it now draws against the full
      screen rect below the box instead of competing with content inside it
- [x] 12.4 Removed the auto-flip setting: the turn handover (Space to flip)
      is unconditional, since it doubles as the readiness signal a future
      timed mode needs and must not be optional
- [x] 12.5 Removed undo and redo from the live game screen — chess does not
      allow taking back a played move. The list-surgery helpers in
      `core/history.c` and the `Move`-carrying history list stay in place,
      reserved for a future "replay a finished game" mode
- [x] 12.6 Fixed an inconsistency between checkmate and stalemate at the end
      of a game: a promotion-delivered win couldn't replace the game screen
      in the same event as an overlay-driven one (resignation, a draw
      accept), so the transition to the result screen waited one extra
      keypress — and in that gap, the result screen recomputed the board's
      orientation from `side_to_move` instead of reusing the live screen's
      last orientation, which could look like the board flipping on its own.
      The orientation is now carried over unchanged; the one-extra-keypress
      wait itself is a known, accepted limit of the screen-stack's Cmd_t
      vocabulary (it cannot pop two screens and push one in a single step)

## 13. Post-implementation revisions, round 2

Further playtesting after round 1 surfaced more real problems, including one
design reversal (automatic saving itself, not just the three-slot picker on
top of it). Addressed in place; see `specs/` for the corresponding
requirement changes.

- [x] 13.1 Fixed the result screen's final-position board: the horizontal and
      vertical rules did not join at their intersections (plain `─`/`│`
      everywhere, no `┬┴┼┌┐└┘├┤`) the way the live board's do; also added the
      checked-king highlight (tinted square plus `!` mark) a checkmate always
      leaves, using the same orientation-continuity fix from 12.6 so it never
      looks like the position quietly changed
- [x] 13.2 Menu screens (main menu, Settings, the result screen) now
      distinguish "select" from "choose": a click or an arrow key only moves
      the highlight, and Enter is the one way to act on it — clicking used to
      act immediately, which could apply the wrong option by accident
- [x] 13.3 The legal-quiet-move dot is now U+2022 (•) instead of U+25CF (●) —
      visibly smaller, since the full circle read as oversized against the
      board
- [x] 13.4 Removed autosave and the "Resume" menu entry entirely, not just
      the three-slot picker that sat on top of them (see 12.2). An automatic
      background save could resume straight into a *finished* game — showing
      a board that looked live when the game had actually already ended —
      which is the outcome-hiding failure this whole change exists to
      prevent. Saving is now always an explicit choice: the save command
      during play, or the save option offered when quitting (13.7)
- [x] 13.5 Saving an opening position with no moves played is now refused —
      there is nothing in it worth keeping
- [x] 13.6 Named saves are now tracked by an id assigned on first save and
      embedded in the filename (`<date>-<id>.chess`) alongside the date;
      every later save of that same game — including one resumed by loading
      it back — updates that one file (`GameState.save_path`) instead of
      creating another. Previously every save created a brand new file, so
      saving the same game repeatedly piled up indistinguishable copies of
      it
- [x] 13.7 Move history's key moved from `m` to Shift-`H`, freeing `m` (no
      longer used) and matching `F` as the other shifted binding; verified
      the scrolling keys the Help/history hint text already claimed
      (arrows, PgUp/PgDn, Home/End) actually work — they did, so the text
      was left as-is rather than trimmed
- [x] 13.8 Quitting a game in progress now asks to save and quit, quit
      without saving, or cancel, replacing a plain yes/no confirmation — the
      moment an in-progress game is preserved, now that there is no
      background autosave to fall back on (see 13.4). Two options, not
      three, when there is nothing to save yet
- [x] 13.9 Found and fixed a real rendering bug while building 13.8: the quit
      and resignation overlays' box heights were one row short of their own
      content, silently clipping the last line (the "Cancel" option, in the
      quit overlay's case) — caught by rendering the actual overlay rather
      than only reasoning about the height arithmetic

## 14. Post-implementation revisions, round 3

A further playtest pass. Round 1 (12.1) made the *menu* screens consistent and
round 2 (13.2) taught them to distinguish "select" from "choose", but both
left the in-game overlays exempt on the grounds that in-game interaction
should be fast. Playing with them showed that exemption was wrong on both
counts, and most of this round is withdrawing it. See `specs/app-shell`,
`specs/board-interaction`, and `specs/game-outcome` for the requirement
changes.

- [x] 14.1 Removed the letter shortcuts from every remaining choice screen —
      the quit overlay's `s`/`q`, the resignation picker's `w`/`b`, the
      draw-offer response's `y`/`n`, and the promotion overlay's
      `1`-`4`/`q`,`r`,`b`,`n` — leaving arrows, Enter, and a click. The
      exemption meant each overlay was a small vocabulary to learn on the
      spot rather than one gesture that works everywhere, and it was the
      *most* consequential choices in the program (resign, agree a draw, quit
      without saving) that were reachable by a single keystroke or click
- [x] 14.2 A click on those overlays now only moves the highlight, as it
      already did on the menu screens (13.2); Enter is the one way to act
- [x] 14.3 Fixed the quit overlay's up arrow, which moved the highlight the
      same way down did — both arms of the `if` ran `(selected + 1) %
      count`. The resignation picker was unaffected (`1 - selected` is its
      own inverse at two options), which is why it went unnoticed
- [x] 14.4 Moved every overlay's hint text out of its own box and onto the
      screen's last row, via a single `app_draw_bottom_hint` helper: the
      Settings overlay was showing its hint twice at once (once in the box,
      once on the row below from the screen beneath), and the resignation
      picker's in-box hint was narrow enough to clip "cancel" to "canc".
      There is now exactly one hint line on screen, and an overlay's replaces
      the game's command row for as long as it is up
- [x] 14.5 Trimmed the saved-game list's and the history screen's hints from
      "↑/↓/PgUp/PgDn/Home/End" to "↑/↓" — the page and Home/End keys still
      work, they are just no longer advertised. 13.7 kept the long form after
      verifying every key in it worked; working was never the objection
- [x] 14.6 Replaced the words "up/down" and "left/right" with ←, →, ↑ and ↓
      throughout the interface
- [x] 14.7 A draw offer is now one keypress rather than two: `o` opens the
      opponent's accept/decline response directly, instead of recording an
      offer that a second `o` then answered. The two-step version existed
      because pass-and-play shares one keyboard and nothing but a move
      changes `side_to_move`, so two presses of `o` could not be told apart —
      but nothing on screen said a second press was what came next, so the
      first press just looked as though it had failed. The response names
      both sides explicitly, which is what actually resolves the ambiguity
- [x] 14.8 Rebuilt the board cursor. It used to be permanent, parked wherever
      it was last left, so two rank and file labels were always highlighted
      with nothing to explain why — the report that started this item was
      "the 'e' and '2' have a different background and I don't know why". It
      now appears on the first arrow press of a turn, at the centre of the
      board; highlights the square it is on as well as that square's labels;
      follows a click or typed square onto whatever is selected; and goes
      away when the move completes or the selection is cancelled. The three
      input methods stay interchangeable — the cursor is now the one place
      all three converge rather than a fourth, separate thing
- [x] 14.9 Found and fixed the same clipped-overlay bug as 13.9, this time in
      the promotion overlay: its box was 7 rows against 4 choices plus a
      title and a blank line, so "Knight" was drawn outside the box and
      dropped. Promotion is the one overlay 13.9's pass did not render,
      because reaching it needs a pawn on the seventh rank
- [x] 14.10 Replaced the resignation picker with a plain confirmation: the
      side to move is the side resigning, and the question is "Resign? X will
      win." rather than "Who resigns?". 10.2 chose the picker because
      pass-and-play shares one keyboard and `side_to_move` only changes on a
      move, so the program cannot tell the two players apart — true, and it
      does mean resigning strictly out of turn is no longer expressible. The
      handover already establishes whose turn it is before either player
      touches a key, so making every resignation answer "who" cost more than
      it saved. The picker's own screen is gone; this is now `confirm_screen`
      with a different message, which is what it should have been
- [x] 14.11 Removed the `F` manual board flip. The handover turns the board
      every turn already, and the only thing a manual flip adds is letting
      the side to move study the position from their opponent's seat
- [x] 14.12 Spelled "H hist" out as "H history" in the status bar — it was
      the only abbreviated entry in the row
- [x] 14.13 The history screen's hint reads "↑/↓ or scroll", not "↑/↓
      scroll", so the mouse wheel is named as the alternative it is
- [x] 14.14 Every choice that ends a game or discards work now opens with the
      highlight on the option that does nothing — "No" on the resign and
      draw-agreement confirmations, "Cancel" on the quit overlay (previously
      "Save and quit"). Once 14.2 stopped a click from acting, the opening
      highlight was the one way left to end a game by accident: a single
      reflexive Enter after the command key. Screens with no destructive
      option — Settings, promotion, the main menu, the result screen — still
      open on their first entry
- [x] 14.15 Fixed a build bug found while cutting this change's version: no
      object depended on the `VERSION` file, even though `CPPFLAGS` bakes its
      contents into every one of them. The `.d` files list only the headers a
      source read, and `VERSION` is not one, so editing it rebuilt nothing —
      `make` relinked a binary still reporting the previous version, which is
      exactly what README.md's release procedure (edit, commit, tag) would
      then have tagged. `VERSION` is now a prerequisite of the object rule
- [x] 14.16 Verification: drove the built binary through a pty at 110x34 with
      a reconstructing terminal emulator (screen text, reverse-video map, and
      background-colour runs), covering the main menu, Settings, Help, the
      saved-game list, the history screen, the result screen, the game board,
      and the quit, resignation, draw-response and promotion overlays. This
      is what caught 14.9 and confirmed each box now contains its own last
      line. `make test` stays at 660/660
